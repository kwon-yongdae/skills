# Git 커밋 메시지 작성

## 목적
변경 내용을 보고 아래 고정 형식의 커밋 메시지를 만든다. 제목은 무엇을 바꿨는지, 본문은 왜 바꿨는지를 설명한다. 이 스킬의 형식을 항상 우선하며, 저장소의 기존 커밋 스타일은 따르지 않는다.

## 절차
1. `git status`와 `git diff --staged`로 스테이징된 변경을 확인한다. 스테이징된 내용이 없으면 `git diff`를 보고, 커밋 단위를 나눌 필요가 있는지 먼저 알려준다.
2. 민감 정보 점검을 한다. `.env`, 키, 토큰, 비밀번호, 접속 정보, 개인정보(주민등록번호, 연락처 등)가 스테이징에 섞였는지 확인한다. 있으면 커밋하지 않고 사용자에게 알린다.
3. 변경을 한 가지 목적으로 묶을 수 있는지 판단한다. 서로 다른 목적이 섞였으면 나눠서 커밋하도록 제안한다.
4. 아래 형식으로 메시지를 작성한다.
5. 사용자에게 메시지를 보여주고 승인을 받은 뒤에만 커밋한다. 여러 줄 메시지는 줄바꿈이 깨지지 않도록 HEREDOC으로 넘긴다.

```bash
git commit -F - <<'EOF'
fix(auth): 로그인 5회 실패 시 계정 잠금 적용

실패 횟수 카운터가 세션마다 초기화되어 잠금 조건이 동작하지 않았음.
카운터를 사용자 기준으로 저장하도록 변경하고, 15분 뒤 자동 해제되도록 함.

- 실패 카운터를 사용자 ID 기준으로 저장
- 잠금 해제 시간을 15분으로 설정
- 잠금 상태 안내 문구 추가

Refs: #482
EOF
```

## 형식

```
<타입>(<범위>): <제목>

<본문: 변경 이유와 이전과의 차이>

<변경점이 여러 개면 하이픈 목록, 한 항목당 한 줄>

<꼬리말: 이슈 번호 등, 있을 때만>
```

- 타입: `feat`(기능 추가), `fix`(버그 수정), `docs`(문서), `style`(포맷, 세미콜론 등 동작 무관 변경), `refactor`(리팩터링), `perf`(성능 개선), `test`(테스트), `build`(빌드, 의존성), `ci`(CI 설정), `chore`(그 밖의 잡무), `revert`(되돌리기)
- 범위: 실제 디렉토리나 모듈 이름을 쓴다(예: `auth`, `order`, `api`). 명확하지 않으면 생략한다.
- 제목: 50자를 권장한다. 넘으면 핵심 키워드만 남기고 나머지는 본문으로 옮긴다. 명령형 현재시제로 쓰고 끝에 마침표를 붙이지 않는다.
- 본문: 한 줄을 72자 안팎으로 줄바꿈한다. "무엇을"보다 "왜"를 적고, 이전 동작과 달라진 점을 쓴다.
- 변경점: 두 개 이상이면 하이픈 목록으로 한 항목당 한 줄씩 적는다.
- 꼬리말: 이슈 번호 표기는 예외적으로 트래커 규칙을 따른다(GitHub는 `Refs: #123`, Jira는 `Refs: PROJ-123` 등). 그 외 커밋 형식은 이 문서를 그대로 따른다. 호환성이 깨지면 반드시 `BREAKING CHANGE: ...`를 적는다.

## 언어
- 기본값: 제목과 본문은 한국어, 타입 접두사와 기술 용어(API, DB 등)는 영어 그대로 쓴다.
- 사용자가 영어로 요청하면 영어로 쓴다.

## 예시

feat (기능 추가)
```
feat(order): 주문서 엑셀 내려받기 기능 추가

영업팀이 주문 내역을 직접 집계하느라 시간이 오래 걸려 요청이 많았음.
주문 목록 화면에 엑셀 다운로드 버튼을 추가함.

- 조회 조건을 그대로 반영해 내려받도록 함
- 최대 10만 행까지 내려받을 수 있도록 제한
```

chore (잡무)
```
chore(deps): 날짜 처리 라이브러리 2.4.1로 올림

보안 권고가 있는 이전 버전을 사용 중이었음.
API 변경은 없으며 기존 테스트 전부 통과 확인.
```

revert (되돌리기)
```
revert: fix(auth): 로그인 5회 실패 시 계정 잠금 적용

운영 배포 후 정상 사용자 일부가 잠기는 문제가 발생해 되돌림.
원인 분석 후 다시 적용 예정.

This reverts commit 3f2a9c1.
```

## 금지 사항
- `Co-Authored-By`, `Generated with Claude` 등 AI 작성 표시 줄을 넣지 않는다. 커밋 작성자는 사용자 본인 이름만 남긴다.
- 제목에 "수정함", "변경함"처럼 의미 없는 말만 쓰지 않는다. 구체적으로 쓴다.
- 민감 정보가 포함된 상태로 커밋하지 않는다.
- 사용자가 승인하지 않은 상태에서 커밋하거나 push하지 않는다.

## 체크리스트
- [ ] 민감 정보가 스테이징에 없는가
- [ ] 한 커밋이 한 목적만 담고 있는가
- [ ] 제목이 타입 접두사를 갖추고 50자 안팎인가
- [ ] 본문이 "왜"를 설명하는가
- [ ] 변경점이 여러 개면 하이픈 목록으로 적었는가
- [ ] 이슈 번호가 트래커 표기에 맞는가
- [ ] 호환성이 깨지면 `BREAKING CHANGE:`를 적었는가
- [ ] AI 작성 표시 줄이 없는가
